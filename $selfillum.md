## $selfillum (Статичное самосвечение)

Это базовый параметр [[Шейдеры|шейдера]] материала в движке [[Source Engine 1|Source]], активирующий режим **самосвечения** (излучения света) для определенных участков поверхности. Он поддерживается всеми ключевыми шейдерами, включая `VertexLitGeneric` (для моделей) и `LightmappedGeneric` (для брашей уровней).

Ключевые особенности механики

- **Принцип работы:** Участки текстуры, отмеченные маской самосвечения, полностью игнорируют карты динамического и статического затенения сцены. Они всегда выводятся на экран со стопроцентной яркостью диффузной карты ([[$basetexture]]), симулируя эффект того, что объект «горит» изнутри в абсолютной темноте.
- **Отличие от `$emissiveblend`:** В отличие от продвинутого конвейера [[$emissiveblend]], который накладывает независимый движущийся оверлей, `$selfillum` является статичным. Он жестко привязан к UV-развертке базовой текстуры и не может скроллиться или деформироваться отдельно от неё.
- **Цветовое пространство:** Маска самосвечения сэмплируется движком в цветовом пространстве **Linear (Data)**, что критически важно для предотвращения искажения полутонов и размытия светящихся контуров.

## 📐 Архитектура и синтаксис в VMT

Включение базового самосвечения требует объявления флага `$selfillum` и настройки сопутствующих коэффициентов управления яркостью и цветом.

Базовый синтаксис VMT-кода:

vmt

```
"VertexLitGeneric"
{
	"$basetexture"       "models/props/neon_sign"
	"$bumpmap"           "models/props/neon_sign_normal"
	
	// Активация самосвечения
	"$selfillum"         "1"
	
	// Настройка силы и оттенка свечения
	"$selfillumtint"     "[1.0 1.0 1.0]"  // Множитель яркости по RGB-каналам
	"$selfillummask"     "models/props/neon_sign_glow" // Опционально: внешняя маска
}
```

Используйте код с осторожностью.

## 📦 Методы маскирования и упаковка каналов

По умолчанию включение команды `"$selfillum" "1"` заставит светиться абсолютно всю поверхность объекта. Чтобы изолировать свет (например, чтобы у радиоприемника светилась только шкала частот, а деревянный корпус оставался темным), Source предлагает два метода маскирования:

Метод 1. Использование альфа-канала базовой текстуры (По умолчанию)

Самый экономичный метод, не требующий создания лишних файлов. Движок по умолчанию ищет маску свечения в **альфа-канале файла `$basetexture`**.

- **Белые пиксели (255) в альфе:** Участок светится на максимальную мощность.
- **Чёрные пиксели (0) в альфе:** Участок полностью игнорирует самосвечение и затеняется по общим законам физики.

Метод 2. Использование внешней текстуры-маски (`$selfillummask`)

Если альфа-канал базовой текстуры уже занят под другие нужды (например, под маску прозрачности или выборочную покраску), маску свечения можно вынести в отдельный независимый файл формата `.vtf` (Grayscale) с помощью команды:

vmt

```
	"$selfillummask"     "models/props/neon_sign_glow"
```

Используйте код с осторожностью.

⚠️ **Важно:** Если объявлен параметр `$selfillummask`, движок полностью перестает читать альфа-канал базовой текстуры для расчета свечения.

## ⚙️ Продвинутые параметры управления

Для управления поведением светящихся участков используются следующие сопутствующие команды:

- **`$selfillumtint <vector>`** — трехкомпонентный вектор, выполняющий роль RGB-фильтра и множителя яркости.
    - Позволяет искусственно выкрутить яркость свечения в кастомных форках движка или окрасить белое свечение в нужный оттенок (например, `"[0.0 2.0 0.0]"` сделает диоды ядовито-зелеными).
- **`$selfillum_envmapmask_alpha`** — (зависит от ветки движка) уникальный коэффициент, позволяющий использовать маску самосвечения одновременно в качестве маски для отражений кубмапов ([[$envmapmask]]).

## 🛑 Известные баги, конфликты и технические ограничения

- **Объект не освещает мир вокруг себя (Фейковое свечение):**
    - _Причина:_ Это архитектурное ограничение движка Source 1. Параметр `$selfillum` — это исключительно визуальный эффект шейдера для конкретного материала. Он делает объект ярким для глаз игрока, но **не испускает честных динамических фотонов света** в пространство. Окружающие стены и пропсы останутся темными.
    - _Решение:_ На картах в Hammer Editor мапперы обязаны вручную размещать невидимые источники динамического света (`light_dynamic`) или статичные лампы (`light`) вплотную к светящейся модели. В Garry's Mod для этого используют Lua-функцию `DynamicLight()`.
- **Критический конфликт с прозрачностью (`$translucent`) и покраской (`$blendtintbybasealpha`):**
    - _Причина:_ Как подробно разбиралось в статьях [[$envmapmask]] и [[Динамическая покраска моделей|динамической покраске]], альфа-канал базовой текстуры — это единый ресурс. Вы **не можете** одновременно использовать альфу `$basetexture` для прозрачности стекол, маски покраски одежды и маски самосвечения. Шейдер аппаратно запутается в приоритетах и полностью сломает рендер материала.
    - _Решение:_ Выносить маску свечения во внешний файл через `$selfillummask`, освобождая альфа-канал базовой текстуры под нужды прозрачности или покраски.
- **Светящиеся элементы выглядят размытыми и «зубчатыми» в темноте:**
    - _Причина:_ Некорректный формат сжатия маски при импорте в VTFEdit. Формат сжатия DXT1 грубо квантует полутона, превращая мягкие переходы светящегося неонового контура в рваные пиксельные пики.
    - _Решение:_ Использовать формат **DXT5** для сохранения плавных 8-битных градиентов маски, либо несжатый формат **BGRA8888** для фокусных элементов интерфейсов и приборов.
