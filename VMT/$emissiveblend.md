## $emissiveblend (Продвинутое самосвечение)

Это специализированный технологический конвейер внутри пиксельного [[Шейдеры|шейдера]] `VertexLitGeneric` в движке [[Source Engine 1|Source]], предназначенный для создания сложного, динамического и анимированного самосвечения на моделях. Он был разработан Valve для эффектов пульсирующих энергетических ядер в _Portal 2_ и светящихся элементов инопланетного оружия в _Alien Swarm_.

Ключевые особенности механики

- **Отличие от классического `$selfillum`:** Стандартная команда `$selfillum` просто заставляет альфа-канал базовой текстуры статично гореть в темноте с постоянной силой. Конвейер `$emissiveblend` — это полноценный вторичный оверлей. Он берет независимую текстуру свечения, накладывает её поверх модели по специальной маске, позволяет ей бесконечно двигаться (скроллиться) и динамически менять яркость.
- **Игнорирование света:** Текстура, пропущенная через этот конвейер, полностью игнорирует любые внешние источники освещения (лампы, солнце, фонарик) и выводится на экран с абсолютной яркостью, заданной в VMT.
- **Цветовое пространство:** Карты масок и векторов для этого конвейера всегда обрабатываются в пространстве **Linear (Data)**, в то время как сама цветная текстура свечения сэмплируется в **sRGB**.

## 📐 Архитектура и синтаксис в VMT

Настройка `$emissiveblend` требует обязательного объявления **четырех независимых текстурных слотов** и набора скалярных коэффициентов. Пропуск хотя бы одного обязательного параметра полностью отключает эффект.

Базовый синтаксис VMT-кода:

vmt

```
"VertexLitGeneric"
{
	"$basetexture" "models/props/sci_fi_core"
	"$bumpmap"     "models/props/sci_fi_core_normal"

	// 1. Активация конвейера продвинутого свечения
	"$emissiveblendenabled"         "1"

	// 2. Подключение текстурных карт
	"$emissiveblendbasetexture"    "models/props/core_glow_energy" // Текстура самого свечения (RGB)
	"$emissiveblendflowtexture"    "dev/null"                      // Карта направленного потока (для деформации, обычно dev/null)
	"$emissiveblendtexture"        "models/props/core_glow_mask"   // Текстура-маска (Grayscale). Определяет форму свечения.

	// 3. Скалярные параметры и коэффициенты
	"$emissiveblendtint"           "[1.0 1.0 1.0]"                 // Множитель цвета и силы свечения (RGB)
	"$emissiveblendscrollvector"   "[0.0 0.0]"                     // Вектор скорости движения текстуры [X Y]
	
	// Внутренний системный буфер (нужен для корректного расчета матриц на GPU)
	"$emissiveblendstrength"       "1.0"                           
}
```

Используйте код с осторожностью.

## ⚙️ Функционал параметров и упаковка карт

Для создания качественного эффекта (например, эффекта текущей внутри прибора жидкой плазмы или пульсирующего неонового паттерна) необходимо четко понимать роль каждой карты:

- **`$emissiveblendbasetexture`** — это рисунок, который будет излучать свет. Обычно это бесшовная текстура энергетических дорожек, шума, фракталов или пламени.
- **`$emissiveblendtexture`** — статичная маска, вшитая в UV-развертку модели. Белые участки маски разрешают свечение, черные — полностью блокируют его (чтобы энергия горела только внутри предназначенных для этого стеклянных колб или пазов прибора).
- **`$emissiveblendscrollvector`** — двухкомпонентный вектор, который заставляет текстуру энергии бесконечно двигаться по осям U и V со смещением. Значение `"[0.1 0.0]"` заставит плазму бесконечно течь вправо.
- **`$emissiveblendtint`** — главный регулятор. Работает как цветовой HDR-фильтр. Если передать значения выше единицы (например, `"[10.0 5.0 0.0]"`), шейдер вызовет сильный эффект Bloom (свечение будет ослепительно-оранжевым и начнет мягко размываться на краях экрана, имитируя раскаленный металл или лазер).

## 🎞️ Практический пример: Создание пульсирующего реактора с бегущей плазмой

Скомбинировав параметры `$emissiveblend` со встроенными математическими шейдерными скриптами — **[[Proxies]]**, можно превратить статичную модель в живой анимированный проп для Garry's Mod без использования тяжелых покадровых текстур `.vtf`.

vmt

```
"VertexLitGeneric"
{
	"$basetexture" "models/props/reactor"
	"$bumpmap"     "models/props/reactor_normal"

	// Конфигурация Emissive Blend
	"$emissiveblendenabled"         "1"
	"$emissiveblendbasetexture"    "models/props/plasma_noise" // Текстура шума плазмы
	"$emissiveblendflowtexture"    "dev/null"
	"$emissiveblendtexture"        "models/props/reactor_glow_mask" // Маска пазов реактора
	
	"$emissiveblendtint"           "[0.0 2.0 5.0]"             // Бирюзовое свечение по умолчанию
	"$emissiveblendscrollvector"   "[0.05 0.1]"                // Плазма медленно течет по диагонали
	"$emissiveblendstrength"       "1.0"

	"Proxies"
	{
		// Создаем синусоидальную пульсацию для имитации нестабильной работы ядра
		"Sine"
		{
			"resultVar"    "$emissiveblendstrength" // Управляем силой наложения
			"sineperiod"   "1.5"                    // Цикл пульсации: 1.5 секунды
			"sinemin"      "0.3"                    // В пике затухания ядро слегка тускнеет
			"sinemax"      "2.0"                    // В пике активности горит в два раза ярче
		}
	}
}
```

Используйте код с осторожностью.

## 🛑 Известные баги, лимиты и технические ограничения

- **Критический вылет из-за знака умножения в векторе:**
    - _Причина:_ Параметр `$emissiveblendscrollvector` жестко ожидает только два числа в квадратных скобках `"[X Y]"`. Если по ошибке прописать туда три числа `"[0 0 0]"` (как для `$color2`), пиксельный шейдер наткнется на неверную размерность матрицы, что вызовет моментальное закрытие игры без генерации лога ошибки (Engine Crash).
- **Свечение полностью пропадает при включении фонарика (Flashlight):**
    - _Причина:_ Старый баг оригинального конвейера рендеринга Source 1. Динамический фонарик игрока использует тяжелый прожекторный шейдер Forward-рендеринга, который при прямом наведении луча на модель может аппаратно перекрывать и «тушить» слой `$emissiveblendbasetexture`.
    - _Решение:_ В кастомных модах и свежих сборках Garry's Mod этот конфликт частично решен на уровне кода рендерера, но в качестве подстраховки рекомендуется не выкручивать яркость диффуза модели в абсолютный ноль.
- **Текстура свечения двигается рывками или «лагает» на дальней дистанции:**
    - _Причина:_ Отсутствие сгенерированных Mip-уровней (мип-маппинга) на файле, указанном в строке `$emissiveblendbasetexture`. При отдалении камеры возникает шейдерный алиасинг, и мелкие пиксели шума плазмы превращаются в хаотично мерцающую кашу.
    - _Решение:_ При импорте текстуры энергии в VTFEdit Reloaded всегда проверяйте, чтобы была активна галочка **Generate Mipmaps**.
