## Шейдеры (Shader)

В движке [[Source Engine 1|Source]] **шейдеры** представляют собой специализированные микропрограммы (скомпилированный C++ код), исполняемые непосредственно на графическом процессоре (GPU). Они определяют, по каким именно математическим алгоритмам будет визуализироваться геометрия (расчет освещения, рельефа, отражений и прозрачности).

Инструкции для шейдеров прописываются текстовых файлах материалов **VMT (Valve Material Type)**. Каждая VMT-статья обязана начинаться с объявления имени корневого шейдера.

## 🏗️ Классификация и типы шейдеров

Конвейер Source разделяет шейдеры на две основные категории в зависимости от типа обрабатываемой геометрии:

1. Брашевые шейдеры (World / BSP-геометрия)

Используются для стен, полов, ландшафта и других статичных элементов уровня, созданных в Hammer Editor. Оптимизированы для работы со статичными картами освещения (**Lightmaps**).

- **`LightmappedGeneric`** — самый массовый шейдер движка. Отрисовывает стандартные поверхности, поддерживает карты нормалей, детальные текстуры и кубмапы.
- **`WorldVertexTransition`** — специализированный шейдер блендинга. Позволяет плавно смешивать две разные базовые текстуры (и их карты нормалей) по маске Vertex Paint (окраске вершин). Используется для создания дорог, травы, стыков земли и стен.

2. Модельные шейдеры (Studio Models)

Используются для динамических и статичных трехмерных моделей (`.mdl`), импортированных из 3D-пакетов (персонажи, оружие, физические пропсы). Оптимизированы для динамического повершинного и попиксельного освещения.

- **`VertexLitGeneric`** — главный шейдер для моделей. Обладает самым широким функционалом аппаратной симуляции материалов. Поддерживает [[$phong]], динамические отражения и подповерхностное рассеивание.
- **`UnlitGeneric`** — шейдер, полностью игнорирующий любые источники света (статичные лампы, солнце, фонарик). Текстура выводится со стопроцентной яркостью. Применяется для элементов интерфейса (HUD), скайбоксов (`Sky`), индикаторов, экранов и светящихся текстур пламени/эффектов.

## 🎛️ Анатомия взаимодействия: Шейдер и VMT-команды

Сам по себе шейдер — это жесткий каркас логики. То, как именно он себя ведет, разработчик настраивает через ключи (параметры) в VMT. Шейдер выступает в роли диспетчера, распределяющего текстурные каналы по математическим формулам:

vmt

```
"VertexLitGeneric" // 1. Объявление шейдера (Модель с динамическим светом)
{
	// 2. Входные текстурные карты (Сэмплеры)
	"$basetexture"  "models/prop/wood_box"
	"$bumpmap"      "models/prop/wood_box_normal"

	// 3. Переключатели логики шейдера (Boolean)
	"$phong"        "1" 
	
	// 4. Математические константы и коэффициенты (Floats / Vectors)
	"$phongboost"   "1.5"
	"$phongfresnelranges" "[0.1 0.5 1.0]"
}
```

Используйте код с осторожностью.

## 🛑 Аппаратные ограничения и архитектурные конфликты

Шейдерный конвейер Source изначально проектировался под стандарты DirectX 9 (шейдерные модели Vertex/Pixel Shader 2.0 и 3.0). Это накладывает ряд жестких ограничений, актуальных для всех ветвей движка:

- **Лимит интерполяторов (UV Merging):**  
    Количество каналов данных, передаваемых от вершинного шейдера к пиксельному, строго ограничено. По этой причине в `VertexLitGeneric` архитектурно невозможно заставить матрицы `$basetexturetransform`, `$bumptransform` и `$detailtransform` двигаться полностью независимо друг от друга. Шейдер «склеивает» их UV-координаты для оптимизации.
- **Конфликт альфа-каналов:**  
    Пиксельный шейдер сэмплирует текстуру целиком. Если в коде прописаны команды, претендующие на один и тот же альфа-канал (например, расчет прозрачности `$translucent` и чтение маски зеркальности `$basealphaenvmapmask`), логика шейдера ломается. Разработчик обязан жестко распределять маски по разным текстурным контейнерам.
- **Отсутствие честного PBR (Physically Based Rendering):**  
    Шейдеры классического Source не умеют работать с современными картами _Metallic_ и _Roughness_. Чтобы перенести PBR-материал из Substance Designer в Source, его параметры приходится вручную инвертировать и распределять: _Roughness_ конвертируется в экспоненту и маску Phong, а _Metallic_ имитируется через точечную настройку контраста кубмапов `$envmapcontrast`.

## 🛠️ Специфические и редкие шейдеры движка

Помимо базовых, Source включает в себя семейство узкоспециализированных шейдеров:

- **`Refract`** — шейдер преломления света. Используется для создания реалистичных стекол, линз прицелов, оптического камуфляжа и эффектов горячего воздуха от взрывов. Требует карту нормалей для смещения пикселей заднего плана.
- **`Water`** — один из самых сложных шейдеров движка. Рассчитывает отражения (через рендер-текстуру), преломления, глубину тумана под водой и динамическую плоскость разреза.
- **`Sprite` / `UnlitSprite`** — шейдеры для двумерных частиц и систем частиц (эффекты дыма, искр, лазерных лучей), которые всегда развернуты лицом к камере игрока (Billboard-эффект).
- **`Teeth` / `Eyes`** — специализированные шейдеры для рендеринга глаз и зубов персонажей, учитывающие влажность, кривизну роговицы и специфический взгляд на источник света.
