## Proxies (Текстурные прокси)

**Proxies** — это динамический скриптовый блок внутри файла материала (VMT), который позволяет изменять параметры [[Шейдеры|шейдера]] прямо во время игры. С помощью прокси статичные текстуры превращаются в динамические: они могут бесконечно двигаться, пульсировать, реагировать на здоровье игрока, скорость движения, триггеры на карте или внутриигровое время.

Ключевые особенности механики

- **Принцип работы:** Прокси выступает в роли посредника (шлюза) между игровым движком и пиксельным/вершинным шейдером. Он берет динамическую переменную из игры (например, текущую скорость игрока или фазу синусоиды) и каждую секунду перезаписывает её в целевой параметр VMT (например, в `$detailblendfactor` или `$basetexturetransform`).
- **Производительность:** Прокси выполняются на стороне CPU перед отправкой кадра на отрисовку. Использование сотен материалов с тяжелыми прокси в одной сцене может снизить общую производительность (FPS).

## 📐 Синтаксис и структура в VMT

Блок `Proxies` всегда объявляется в самом конце VMT-файла перед закрывающей фигурной скобкой. Внутри него можно инициализировать сразу несколько скриптов, которые будут выполняться последовательно.

vmt

```
"VertexLitGeneric"
{
	"$basetexture" "models/props/power_core"
	"$detail"      "models/props/power_core_glow"
	"$detailblendmode" "5" // Светящийся оверлей
	"$detailblendfactor" "1.0"

	// Начало блока динамических скриптов
	"Proxies"
	{
		// Имя встроенного прокси-генератора
		"Sine"
		{
			// 1. Выходной параметр (Куда записывать результат)
			"resultVar"    "$detailblendfactor"
			
			// 2. Входные настройки скрипта
			"sineperiod"   "3.0"  // Время полной пульсации в секундах
			"sinemin"      "0.2"  // Минимальная яркость
			"sinemax"      "1.5"  // Максимальная яркость
		}
	}
}
```

Используйте код с осторожностью.

## 🛠️ Основные типы прокси и примеры их применения

Движок Source содержит десятки встроенных прокси-функций. Их можно разделить на три основные группы:

1. Генераторы волновых функций (Автоматическая анимация)

Работают автономно от систем карты, генерируя бесконечные циклы математических значений.

- **`LinearRamp`** — бесконечно увеличивает значение с заданной скоростью. Идеален для создания бегущих текстур (скроллинга воды, конвейерных лент, облаков).
- **`Sine`** — генерирует плавную синусоидальную волну. Используется для мерцания лампочек, пульсации энергии или дыхания био-материалов.

**Пример бесконечного движения (скроллинга) базовой текстуры:**

vmt

```
		"LinearRamp"
		{
			"rate"      "0.5"                 // Скорость смещения в секунду
			"resultVar" "$basetexturetransform" // Двигает UV-координаты диффуза
		}
```

Используйте код с осторожностью.

_Примечание:_ Как указано в статье [[$basetexture]], из-за лимита интерполяторов этот прокси заставит двигаться и карту нормалей [[$bumpmap]].

2. Управленцы текстурными контейнерами

Позволяют управлять кадрами многокадровых файлов `.vtf`.

- **`AnimatedTexture`** — классический прокси для циклического воспроизведения покадровой анимации (экраны телевизоров, огонь, бегущие строки).
- **`ToggleTexture`** — останавливает анимацию на конкретном кадре. Кадр переключается внешней энтити с карты (например, через триггер Hammer Editor при нажатии кнопки в игре).

3. Игровые интеграторы (Взаимодействие с миром)

Считывают реальные физические параметры из игрового мира.

- **`MaterialModify`** — универсальный прокси для связи материала с I/O системой карты. Позволяет мапперам менять любые параметры VMT через энтити `material_modify_control`.
- **`PlayerSpeed`** / **`PlayerHealth`** — считывают текущую скорость или здоровье игрока. Полезно для создания эффекта размытия на очках персонажа или индикаторов на костюме.
- **`EntityRandom`** — генерирует случайное статичное число при спавне объекта. Позволяет сделать так, чтобы одинаковые пропсы (например, ящики или трупы) имели разную степень загрязнения или разные кадры через `ToggleTexture`.

## 🧮 Математические прокси (Арифметика внутри VMT)

Если вам нужно связать игровой параметр со сложной формулой шейдера, Source позволяет проводить базовые математические расчеты между переменными VMT прямо на лету:

- **`Add`** — складывает два параметра и записывает в третий.
- **`Subtract`** — вычитает значения.
- **`Multiply`** — умножает параметры.
- **`Clamp`** — жестко ограничивает диапазон переменной (например, не дает результату умножения уйти выше `1.0` или упасть ниже `0.0`).

**Пример связки: считывание здоровья игрока и умножение его на силу Phong-блеска:**

vmt

```
	"Proxies"
	{
		// 1. Получаем здоровье (значение от 0 до 100)
		"PlayerHealth"
		{
			"resultVar" "$phongboost" 
		}
		// 2. Зажимаем его в диапазон от 0.0 до 1.0 для корректной математики
		"Clamp"
		{
			"min"       "0.0"
			"max"       "1.0"
			"srcVar1"   "$phongboost"
			"resultVar" "$phongboost"
		}
	}
```

Используйте код с осторожностью.

## 🛑 Известные баги и архитектурные ограничения

- **Критический вылет из-за некорректного типа данных:**  
    Прокси очень чувствительны к типам переменных. Если передать значение типа _Vector_ `"[0 1 0]"` в прокси, который ожидает одиночное число _Float_ (например, в `sineperiod`), движок мгновенно завершит работу с ошибкой доступа к памяти (Engine Crash).
- **Игнорирование прокси статичной геометрией (`LightmappedGeneric`):**  
    Ряд игровых прокси (такие как `PlayerSpeed`, `PlayerTeam`, `Health`) физически не могут работать на брашах стен или полов. Они рассчитаны строго на динамические сущности (`VertexLitGeneric` на моделях персонажей/оружия). Брашевая геометрия способна обрабатывать только автономную математику вроде `Sine`, `LinearRamp` и `AnimatedTexture`.
- **Конфликт принудительного перезаписывания:**  
    Если два разных прокси внутри одного материала попытаются одновременно изменять одну и ту же переменную (например, `$detailblendfactor`), они не сложатся. Выполнится только тот прокси, который объявлен в блоке ниже по тексту, полностью затерев расчеты предыдущего. Для сложения нужно использовать математический прокси `Add`.
