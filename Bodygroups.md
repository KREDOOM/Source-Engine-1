## Bodygroups (Бодигруппы)

**Bodygroups** — это встроенный механизм движка [[Source Engine 1|Source]], позволяющий объединять внутри одного файла модели (`.mdl`) несколько альтернативных наборов геометрии (подмоделей) и динамически переключать их во время игры.

Ключевые особенности механики

- **Принцип работы:** Вместо того чтобы создавать десятки отдельных тяжелых файлов моделей для каждой вариации объекта, разработчик компилирует одну модель, внутри которой упакованы все возможные элементы. Движок скрывает ненужные треугольники и визуализирует только выбранную группу геометрии.
- **Применение в Garry's Mod:** Бодигруппы являются основным стандартом для кастомных игровых моделей. Они используются для кастомизации персонажей (смена одежды, головных уборов, лиц), тюнинга автомобилей (замена бамперов, спойлеров) и модификации оружия (установка прицелов, глушителей).
- **Управление:** Индексы бодигрупп могут переключаться картостроителями через I/O систему Hammer Editor, программистами через Lua-функцию `Entity:SetBodygroup()`, а также самими игроками через контекстное меню (C-меню) Garry's Mod.

## 📐 Архитектура и синтаксис в файле компиляции (.QC)

Объявление бодигрупп происходит в теле `.qc` файла с помощью команды **`$bodygroup`**. Синтаксис чувствителен к порядку перечисления файлов: каждому элементу внутри группы компилятор присваивает порядковый номер (индекс), начиная с `0`.

Базовый синтаксис блока команды:

```qc
$bodygroup "Имя_Группы_В_Игре"
{
	studio "имя_файла_первой_вариации.smd"  // Индекс 0 (По умолчанию)
	studio "имя_файла_второй_вариации.smd"  // Индекс 1
	studio "имя_файла_третьей_вариации.smd"  // Индекс 2
	blank                                   // Индекс 3 (Опционально: пустота/скрыть все)
}
```

Используйте код с осторожностью.

## 🛠️ Практический пример: Компиляция персонажа со шлемом

Рассмотрим классический пример `.qc` скрипта для модели персонажа, у которого можно заменить стандартный шлем на тактические очки или полностью скрыть головной убор.

```qc
$modelname "player/custom_soldier.mdl"
$cdmaterials "models/player/custom_soldier/"

// Базовое, неизменяемое тело (Референс-меш)
$body "body" "soldier_torso_legs.smd"

// Настройка бодигруппы головного убора
$bodygroup "headgear"
{
	studio "soldier_helmet_classic.smd"   // Индекс 0: Обычный шлем
	studio "soldier_tactical_goggles.smd" // Индекс 1: Только очки
	blank                                 // Индекс 2: Пустая голова (без уборов)
}

// Обязательная базовая анимация
$sequence "idle" "soldier_torso_legs.smd" fps 1
```

Используйте код с осторожностью.

Как это работает в игре (Индексация данных):

При спавне модели `headgear` всегда будет находиться в состоянии `0` (игрок увидит `soldier_helmet_classic.smd`).  
Если в коде Lua прописать команду `self:SetBodygroup(1, 1)`, движок моментально скроет шлем и отрендерит вместо него модель очков. Первая цифра в функции означает ID группы (считая сверху вниз от базового `$body`, который равен `0`), вторая цифра — индекс подмодели внутри этой группы.

## 📦 Скин-группы ($texturegroup) как расширение бодигрупп

Если вам нужно изменить не геометрию модели, а только её раскраску (текстуру) — например, перекрасить машину из красной в синюю или добавить персонажу камуфляж — использовать бодигруппы неэффективно. Для этого применяется команда **`$texturegroup`** (скин-группы).

```qc
$texturegroup "skinfamilies"
{
	{ "soldier_armor"          "soldier_face" } // Скин 0 (По умолчанию)
	{ "soldier_armor_camo"     "soldier_face" } // Скин 1 (Камуфляж)
	{ "soldier_armor_medic"    "soldier_face" } // Скин 2 (Медик)
}
```

Используйте код с осторожностью.

_Логика работы:_ Движок берет базовый материал, назначенный на модель в 3D-редакторе (например, `soldier_armor.vmt`), и при переключении скина на `1` подменяет его на `soldier_armor_camo.vmt`. Текстуры, которые не меняются (например, лицо `soldier_face`), обязаны дублироваться в каждой строке массива.

## 🛑 Известные баги, лимиты и технические ограничения

- **Критический лимит на количество вершин (Vertex Limit Crash):**  
    Как упоминалось в статье [[Модели]], Source 1 имеет жесткий лимит на количество вершин внутри одного файла геометрии (`.smd`). При использовании бодигрупп этот лимит работает коварно: компилятор суммирует полигонаж **всех** файлов, подключенных в бодигруппы. Если суммарный объем треугольников базового тела и всех шлемов/обвесов превысит лимит, компиляция завершится ошибкой.
    - _Решение:_ Экспортировать элементы бодигрупп в максимально оптимизированном низкополигональном виде (Low-Poly).
- **Баг «Сломанных теней» (Shadow Artifacts):**
    - _Причина:_ Движок Source генерирует динамические тени от объекта, основываясь на общей коллизии или референс-меше. Если у вас в бодигруппе скрыт огромный рюкзак (выбран индекс `blank`), его геометрия исчезнет, но динамическая тень от рюкзака может продолжать падать на стену позади персонажа.
    - _Решение:_ Использовать в `.qc` команду `$mostlyopaque`, которая заставляет рендерер теней пересчитывать силуэт модели строго по фактически активным в данный момент индексам подмоделей.
- **Конфликт привязки костей (Rigging Glitches):**  
    Каждая подмодель внутри бодигруппы (например, сменный воротник или кобура) обязана быть привязана к той же самой иерархии костей (скелету), что и базовое тело модели. Если импортировать подмодель, привязанную к костям с другими именами или измененным масштабом, при переключении бодигруппы в игре этот элемент улетит в нулевые координаты карты или жестко растянется по экрану.
