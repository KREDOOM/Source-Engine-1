## $detail

Это мощный параметр [[Шейдеры|шейдера]] материала в движке [[Source Engine 1|Source]], предназначенный для наложения вторичной мелкозернистой текстуры поверх базовой альбедо-карты ([[$basetexture]]). Используется для имитации микрорельефа поверхности (поры кожи, волокна ткани, ржавчина, пористость бетона), когда игрок приближается к объекту вплотную.

Ключевые особенности механики

- **Экстремальная экономия памяти:** Вместо создания огромных уникальных текстур высокого разрешения (например, 4K для стены), разработчики используют небольшую базовую текстуру (512x512) и многократно зацикливают (тайлят) поверх нее крошечную текстуру деталей (128x128 или 256x256).
- **Математика смешивания:** В отличие от базовой текстуры, `$detail` не просто перекрывает рисунок, а накладывается по различным математическим алгоритмам (режимам блендинга). По умолчанию используется режим наложения, аналогичный _Overlay_ или _Multiplicative_ в графических редакторах.
- **Цветовое пространство:** Подобно базовой текстуре, детальная карта обрабатывается в пространстве **sRGB**. Для нее критически важна генерация Mip-уровней, так как из-за высокой плотности тайлинга при отдалении камеры без мип-маппинга возникнет сильнейший муар и рябь.

## 📐 Синтаксис VMT

Подключение требует обязательного указания пути к текстуре деталей и коэффициента ее масштабирования (тайлинга).

vmt

```
"VertexLitGeneric"
{
	"$basetexture" "models/props/concrete_wall"
	
	// Подключение детальной текстуры
	"$detail"          "detail/dt_concrete01"
	"$detailscale"     "12.0"                  // Плотность сетки наложения
	"$detailblendfactor" "1.0"                 // Сила проявления (интенсивность)
	"$detailblendmode"   "0"                   // Режим смешивания (0 - Overlay/Decal)
}
```

Используйте код с осторожностью.

## ⚙️ Сопутствующие параметры и тонкая настройка

Для управления поведением детальной карты используется расширенный набор команд:

- **`$detailscale <float или vector>`** — определяет, сколько раз детальная текстура повторится (поместится) внутри одного UV-развертки базовой текстуры.
    - Если задано одно число (например, `12`), текстура масштабируется равномерно по осям X и Y.
    - Можно задавать раздельно через вектор: `"[8 16]"` (растянет деталь по одной из осей).
- **`$detailblendfactor <float>`** — устанавливает прозрачность (интенсивность) наложения детали. Принимает значения от `0.0` (полностью невидима) до `1.0` (максимальная сила). В некоторых кастомных шейдерах и режимах смешивания может принимать значения выше единицы для эффекта свечения.
- **`$detailblendmode <integer>`** — важнейший параметр, определяющий математическую формулу взаимодействия пикселей базовой текстуры и карты деталей:
    - **`0` (Decal / Модифицированный Overlay):** Стандартный режим. Нейтральным является серый цвет (`RGB 128 128 128`). Все, что темнее — затеняет базовую текстуру, все, что светлее — осветляет её.
    - **`1` (Darken / Multiplicative):** Деталь работает как классическая карта _Ambient Occlusion_ или грязь. Только затеняет исходный рисунок. Белый цвет (`RGB 255 255 255`) является нейтральным.
    - **`2` (Lighten / Additive):** Добавляет яркость детальной карты к базовой. Используется для создания эффектов наведенного статического свечения (например, внутренние прожилки лавы, бегущие по камню цифровые дорожки).
    - **`5` (Unlit Additive):** То же самое, что и `2`, но текстура деталей игнорирует динамическое освещение сцены и горит с постоянной яркостью в темноте.
- **`$detailframe <integer>`** — указывает индекс стартового кадра, если детальная текстура является анимированной (многокадровой).

## 🔄 $detailtransform

Матрица двумерного преобразования UV-координат исключительно для детальной текстуры.

vmt

```
"$detailtransform" "center .5 .5 scale 1 1 rotate 0 translate 0 0"
```

Используйте код с осторожностью.

## 🛠️ Скрытая механика: Конфликт с $basetexturetransform

Как уже упоминалось в статье [[$basetexture]], из-за жесткого ограничения на количество интерполяторов в вершинном шейдере DirectX 9, движок Source часто принудительно объединяет (оптимизирует) UV-координаты слоев.

- **Суть проблемы:** Если вы активируете динамическое изменение матрицы базовой текстуры через `$basetexturetransform` (например, заставите текстуру бесконечно бежать с помощью прокси `LinearRamp`), детальный рисунок автоматически «приклеится» к ней и побежит с той же скоростью, полностью игнорируя ваши статические настройки в `$detailtransform`.
- **Исключение:** В ветках движка _Portal 2_, _Left 4 Dead 2_ и _Alien Swarm_ шейдеры получили дополнительный вершинный интерполятор для детализации, что позволяет полностью изолировать движение базового слоя от детального (деталь может оставаться неподвижной, пока базовая текстура под ней скроллится).

## 🛑 Известные баги и особенности оптимизации

- **Эффект «Тайловой сетки» (Тайлинг на расстоянии):**
    - _Причина:_ Если параметр `$detailscale` имеет слишком высокое значение (например, `32` или `64`), при взгляде на объект издалека мелкий рисунок сливается в некрасивую, повторяющуюся сетку или узоры (паттерны).
    - _Решение:_ Подбирайте оптимальный масштаб (обычно от `4` до `16`). Для дальних дистанций используйте качественные Mip-уровни, которые плавно размывают карту деталей в нейтральный серый цвет по мере удаления игрока, полностью нивелируя артефакт.
- **Выбеливание или зачернение материала при некорректном `blendmode`:**
    - _Причина:_ Использование неверной палитры при создании `.vtf` файла для детализации. Например, для `$detailblendmode 0` (Overlay) была создана текстура на абсолютно белом фоне вместо нейтрального серого (`#808080`). Материал в игре станет ядовито-белым.
    - _Решение:_ Четко контролировать среднюю яркость текстуры при экспорте из Substance Designer или Photoshop в зависимости от выбранного режима смешивания.
- **Черные квадраты вместо детализации на старых GPU (Исторический баг):**
    - _Причина:_ В некоторых старых шейдерах принудительное включение `$detail` требовало наличия альфа-канала у базовой текстуры, даже если он не использовался. Без него шейдер падал в ошибку рендеринга девайса. На современных системах практически не встречается.

## 🎞️ Продвинутый пример: Анимированная пульсация энергии

Используя режим смешивания `5` (Unlit Additive) и связку с [[Proxies]], можно превратить статичную текстуру деталей в динамический индикатор здоровья или декоративное свечение прибора.

vmt

```
"VertexLitGeneric"
{
	"$basetexture"       "models/props/sci_fi_generator"
	"$bumpmap"           "models/props/sci_fi_generator_normal"
	
	// Подключение светящихся неоновых дорожек через деталь
	"$detail"            "models/props/energy_circuits"
	"$detailscale"       "1.0"
	"$detailblendmode"   "5"                 // Свечение в темноте
	"$detailblendfactor" "0.5"               // Начальная яркость

	"Proxies"
	{
		// Создаем синусоидальную пульсацию яркости
		"Sine"
		{
			"resultVar"    "$detailblendfactor" // Куда передавать значение
			"sineperiod"   "2.0"                // Время полного цикла в секундах
			"sinemin"      "0.1"                // Минимальная яркость свечения
			"sinemax"      "1.0"                // Максимальная яркость свечения
		}
	}
}
```

Используйте код с осторожностью.
