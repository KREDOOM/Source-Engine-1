## $basetexture

Это фундаментальный параметр [[Шейдеры|шейдера]] материала, доступный во всех версиях движка [[Source Engine 1|Source]]. Он определяет базовую альбедо-текстуру (диффузный цвет, рисунок поверхности).

Ключевые особенности механики

- **Текстура по умолчанию:** Если параметр опущен или путь указан неверно, большинство шейдеров (например, `LightmappedGeneric` или `VertexLitGeneric`) автоматически подставят шахматную черно-пурпурную текстуру (ошибку маппинга) или зальют поверхность сплошным белым цветом (в зависимости от ветки движка).
- **Синергия с рельефом:** Практически всегда используется в паре с картой нормалей [[$bumpmap]], которая рассчитывает объемное затенение поверх базового рисунка.
- **Цветовое пространство:** В отличие от карт нормалей, `$basetexture` всегда обрабатывается движком в цветовом пространстве **sRGB**. При компиляции текстуры в VTFEdit для нее обязательно должны генерироваться Mip-уровни, иначе при отдалении от объекта возникнет жесткий пиксельный шум (шейдерный алиасинг).

## 📐 Синтаксис VMT

Путь к файлу указывается без расширения (`.vtf`) и всегда рассчитывается относительно корневой директории материалов текущей игры или мода (`<game>/materials/`).

vmt

```
"VertexLitGeneric"
{
	"$basetexture"	"brick/brickwall031b"
}
```

Используйте код с осторожностью.

## 🔄 $basetexturetransform

Команда осуществляет двумерное матричное преобразование (аффинные трансформации) UV-координат текстуры перед её передачей на отрисовку шейдеру.

Синтаксис и параметры (Матрица по умолчанию)

vmt

```
"$basetexturetransform" "center .5 .5 scale 1 1 rotate 0 translate 0 0"
```

Используйте код с осторожностью.

⚠️ **Важно:** Все 7 значений и ключевые слова обязаны присутствовать в строке. Пропуск даже одного параметра полностью ломает считывание матрицы.

1. **`center <x> <y>`** — задает локальную точку (в UV-координатах от `0` до `1`), относительно которой будет происходить вращение (`rotate`). По умолчанию `.5 .5` (строго геометрический центр текстуры).
2. **`scale <x> <y>`** — масштабирование (тайлинг). Вписывает текстуру в геометрию указанное количество раз.
    - Значение `2 2` сожмет текстуру в два раза по обеим осям, заставив её повториться 4 раза на той же площади.
    - Значение `0.5 0.5` растянет текстуру, увеличив её визуально в два раза.
3. **`rotate <degrees>`** — вращение текстуры **против часовой стрелки** в градусах. Принимает любые значения, включая отрицательные (например, `-90` развернет текстуру по часовой стрелке).
4. **`translate <x> <y>`** — линейное смещение текстуры по осям U и V. Значение `0.5 0` сдвинет рисунок ровно на половину его ширины вправо. Смещение на `1.0` возвращает текстуру в исходную позицию из-за циклического повторения (тайлинга).

## 🛠️ Скрытая механика: Конфликты интерполяторов (UV Merging)

Трансформация базовой текстуры **может неявно затронуть другие карты** (такие как [[$detail]], [[bumpmap]] и [[$envmapmask]]), даже если для них прописаны собственные матрицы (`$bumptransform` и др.).

- **Почему это происходит:** Программисты Valve жестко оптимизировали вершинный шейдер (Vertex Shader Output). Количество интерполяторов (каналов передачи данных от вершин к пикселям) строго ограничено архитектурой DirectX 9. Чтобы сэкономить каналы, движок принудительно заставляет разные текстурные слои делить общие UV-координаты.
- **Как распределяются приоритеты:** В большинстве веток Source (включая CS:GO, Portal 2, L4D2) трансформации `$basetexture` и `$envmapmask` обычно удается изолировать друг от друга. Однако детальные текстуры (`$detail`) и карты рельефа (`$bumpmap`) практически всегда аппаратно «склеиваются» с матрицей базовой текстуры. Если вы начнете вращать или двигать `$basetexture` через прокси-скрипты, ваш рельеф и детали поплывут вместе с ней.

## 🛑 Известные баги трансформации

- **Сбой Texture Lock в Hammer Editor:** Если в VMT вручную задано масштабирование через `scale`, инструмент «Texture Lock» (фиксация текстуры при изменении формы браша) в редакторе уровней полностью ломается. При перемещении вершин браша текстура на нем начнет хаотично съезжать.
- **Баг вращения на брашах (World-геометрии):** В старых ветках движка (Orange Box / Source 2007) при попытке закрутить текстуру на стенах или полу (`LightmappedGeneric`), центром вращения становится не геометрический центр поверхности и даже не центр текстуры, а глобальная нулевая координата карты `[0, 0, 0]`. В результате текстура улетает далеко за пределы видимости.
    - _Решение:_ Смещать параметр `center` в VMT, подгоняя его под локальные координаты конкретной кисти в Hammer (что крайне непрактично), либо использовать вращение самого браша, оставив VMT в покое.

## 🎞️ $frame

Указывает конкретный индекс кадра, который должен отображаться, если используется многокадровая (анимированная) текстура формата `.vtf`. Индексация кадров всегда начинается с `0`.

vmt

```
"$frame" "4" // Принудительно отобразить 5-й кадр анимации
```

Используйте код с осторожностью.

Применение и автоматизация

Чаще всего этот параметр не прописывается жестко, а управляется динамически во время игры с помощью встроенных шейдерных скриптов — [[Proxies]].

**Пример циклической анимации билборда или экрана:**

vmt

```
"VertexLitGeneric"
{
	"$basetexture" "models/props/screen_anim"
	"$frame" "0" // Начальный кадр
	
	"Proxies"
	{
		"AnimatedTexture"
		{
			"animatedtexturevar"         "$basetexture"
			"animatedtextureframenumvar" "$frame"
			"animatedtextureframerate"   "24" // Скорость: 24 кадра в секунду
		}
	}
}
```

Используйте код с осторожностью.

⚠️ **Внимание (Критический вылет движка):** Значение `$frame` жестко привязано к реальному количеству кадров, запеченных в VTF-файл. Если вы вручную или через прокси передадите индекс, превышающий максимальный (например, попытаетесь вызвать `"$frame" "12"`, когда в текстуре всего 10 кадров), движок моментально завершит работу с критической ошибкой указателя памяти (Engine Crash).

## 📦 Продвинутая упаковка масок (Альфа-канал)

Альфа-канал базовой текстуры является важнейшим ресурсом для оптимизации и активно используется шейдерами для хранения масок:

1. **Маска прозрачности (`$translucent "1"` или `$alphatest "1"`):** Позволяет создавать дыры в геометрии, листву, решетки.
2. **Маска отражений (`$basealphaenvmapmask "1"`):** Указывает, какие зоны материала будут отражать кубмапы ([[$envmap]]). Белые участки альфа-канала — зеркальные, черные — матовые.
3. **Маска самосвечения (`$selfillum "1"`):** В некоторых шейдерах альфа-канал подсвечивает текстуру изнутри в темноте (например, светящиеся неоновые вывески или датчики на костюме).

⚠️ **Критический конфликт масок:** Текстура может иметь только один альфа-канал. Вы **не можете** одновременно использовать альфа-канал `$basetexture` для прозрачности (`$translucent`) и для маски кубмапов (`$basealphaenvmapmask`). Попытка включить их вместе приведет к тому, что прозрачные зоны станут на 100% зеркальными, полностью уничтожив визуализацию материала. При нехватке каналов маску кубмапов необходимо переносить в альфа-канал карты нормалей с помощью команды `"$normalmapalphaenvmapmask" "1"`.
