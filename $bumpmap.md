## 📐 Технические стандарты и каналы (DirectX vs OpenGL)

Движок [[Source Engine 1|Source]] использует строгий стандарт карт нормалей **DirectX (Inverted Y / Y-)**. 
* **Красный канал (R):** Освещение по горизонтали (Слева направо).
* **Зелёный канал (G):** Освещение по вертикали. Направлено **вниз** (в отличие от OpenGL / Blender, где оно направлено вверх). При импорте текстур из сторонних PBR-пакетов в VTFEdit необходимо обязательно ставить галочку **Invert Green Channel**.
* **Синий канал (B):** Отвечает за глубину (направление прямо от поверхности). Во многих современных играх (например, в движке RE Engine из DMC5) этот канал стирается при упаковке для экономии памяти (формат BC5). [[Source Engine 1|Source]] без проблем переваривает такие текстуры нормалей, математически вычисляя координату Z на лету.

## 📦 Упаковка масок и синергия с другими параметрами

Карта `$bumpmap` в шейдере `[VertexLitGeneric]` является главным контейнером для динамического отражения света:

1. **Альфа-канал карты нормалей (Bumpmap Alpha):**
   * Является стандартным местом для хранения маски [[$phong]] (инвертированная карта **Roughness / Глянец** из [[PBR]]). Движок автоматически считывает её оттуда при включении параметра `"$phong" "1"`.
   * Может использоваться для хранения маски зеркальных кубмапов при включении команды `"$normalmapalphaenvmapmask" "1"`.
   * ⚠️ **Критический конфликт:** Команды `$normalmapalphaenvmapmask` и `$phong` нельзя использовать вместе, если они пытаются читать альфа-канал одного и того же бампмапа. Это ломает рендер (эффект "хромированной фольги").

## 🛠️ Расширенный синтаксис и тонкая настройка в VMT

Для управления поведением карты нормалей используются следующие сопутствующие команды:

```vmt
	// Базовое подключение
	"$bumpmap"                    "models/my_project/sword_normal"

	// Управление интенсивностью рельефа
	"$bumpframe"                  "0"             // Кадр анимации (если бамп анимирован)
	"$nodiffusebumplighting"       "1"             // Отключает влияние рельефа на диффузный цвет (оставляет только на бликах)

	// Коэффициенты масштабирования текстуры нормалей относительно геометрии
	"$bumptransform"              "center .5 .5 scale 1 1 rotate 0 translate 0 0"
```

## 🛑 Известные баги и их решение (Troubleshooting)

* **Рельеф выглядит "вывернутым наизнанку":** 
  * *Причина:* Карта нормалей сохранена в формате OpenGL (Y+). Выпуклости на модели будут казаться впадинами, а тени будут падать некорректно относительно солнца.
  * *Решение:* Перекомпилировать текстуру в VTFEdit с инверсией зеленого канала или пропустить через ноду `Normal Invert` в Substance Designer.
* **Артефакты сжатия и "квадраты" на градиентах бликов:**
  * *Причина:* Текстура нормалей скомпилирована в низком формате сжатия (например, DXT1, который полностью уничтожает альфа-канал).
  * *Решение:* При импорте в VTFEdit для файла `$bumpmap` всегда выбирать формат **DXT5** (если используется альфа-маска для Phong) или несжатый **BGRA8888** для идеального качества без пиксельных швов.
