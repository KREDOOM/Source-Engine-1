## Текстуры и материалы (VTF и VMT)

В движке [[Source Engine 1|Source]] визуализация любой поверхности разделена на два компонента: графические данные (бинарный файл) и текстовый скрипт, управляющий логикой отрисовки.

- **Материал** — это комплексная инструкция для видеокарты, объединяющая одну или несколько текстурных карт и набор параметров (команд), которые определяют физические свойства поверхности (глянец, прозрачность, рельеф, реакцию на свет).
- **`.vtf` (Valve Texture Format)** — проприетарный бинарный формат текстур движка Source. Содержит сырые пиксельные данные, каналы (RGB/RGBA), Mip-уровни и специфические флаги компиляции (например, для циклического повторения текстуры). [[1](https://developer.valvesoftware.com/wiki/Ru/Valve_Texture_Format)]
- **`.vmt` (Valve Material Type)** — текстовый конфигурационный файл, написанный на скриптовом языке KeyValues. Он связывает файлы `.vtf` с конкретным [[Шейдеры|шейдером]] и задает коэффициенты их взаимодействия. Движок всегда ищет и накладывает на геометрию именно `.vmt` файл, а не саму текстуру напрямую.

Основной инструментарий

Для создания, конвертации и редактирования ассетов в современной практике моддинга используются:

1. **VTFEdit Reloaded** — современный форк классической утилиты VTFEdit. Является главным инструментом для пакетного импорта стандартных изображений (`.png`, `.tga`, `.jpg`) в формат `.vtf`, генерации правильных Mip-уровней и быстрого написания/правки кода `.vmt`.
2. **VS Code / Notepad++** (с синтаксическим плагином KeyValues) — предпочтительны для глубокой работы со сложными `.vmt` файлами, содержащими объемные блоки [[Proxies]].

---

Анатомия VMT-файла

Файл `.vmt` имеет строгую иерархическую структуру. Любая синтаксическая ошибка (пропущенная кавычка, лишняя фигурная скобка или неверный регистр шейдера) приведет к тому, что материал полностью отключится, а объект в игре покроется черно-пурпурной шахматной сеткой.

## 📐 Базовый синтаксис структуры

vmt

```
"Имя_Шейдера"
{
	// 1. Основные параметры (Текстурные карты)
	"$Ключ" "Путь/К/Файлу/Без/Расширения"

	// 2. Числовые коэффициенты и флаги
	"$Ключ" "Число"
	"$Ключ" "[Вектор Из Трех Чисел]"

	// 3. Динамические блоки и скрипты
	"Блок_Логики"
	{
		// Параметры блока
	}
}
```

Используйте код с осторожностью.

## 🗂️ Три основных блока параметров в VMT

Скрипт материала условно разделен на три функциональные зоны, которые обрабатываются движком последовательно сверху вниз:

1. Объявление корневого шейдера (Root Shader)

Самая первая строка файла. Она пишется в кавычках и определяет, какой C++ алгоритм будет обрабатывать материал. Изменить шейдер «на лету» внутри файла нельзя.

- Примеры для **Garry's Mod**: `"VertexLitGeneric"` (для моделей) или `"LightmappedGeneric"` (для брашей стен/земли). [[1](https://developer.valvesoftware.com/wiki/Ru/Creating_a_Material)]

2. Сэмплеры текстур и скалярные параметры

Основное тело файла. Здесь прописываются пути к текстурам и настраиваются их физические свойства.

- **Пути к файлам:** Всегда указываются без расширения `.vtf` и строго относительно корневой директории материалов игры (`<game>/materials/`). Кавычки обязательны для обеих частей команды.
- **Типы данных параметров:**
    - **Boolean (0 или 1):** Жесткие переключатели функций. Например, `"$phong" "1"` (включить Phong блик) или `"$alphatest" "1"` (включить бинарную прозрачность).
    - **Float (Десятичные дроби):** Множители силы и размеров. Например, `"$phongboost" "1.5"`.
    - **Vector (Массивы данных):** Заключаются в квадратные кавычки `"[R G B]"` для цвета или круглые скобки `"(X Y Z)"` для пространственных координат. Например, цветной фильтр отражений: `"$envmaptint" "[0.5 0.5 0.5]"`.

3. Блок динамических прокси (Proxies)

Объявляется в самом конце файла. Позволяет материалу динамически считывать данные из игры и перезаписывать вышестоящие параметры в реальном времени. Заключается в собственные фигурные скобки.

## 🛑 Критические правила работы с путями и регистрами

- **Регистр шейдеров:** Имена корневых шейдеров чувствительны к регистру в некоторых ветках движка. Писать `"vertexlitgeneric"` маленькими буквами — частая причина багов. Всегда используйте каноничное написание: `"VertexLitGeneric"`.
- **Изоляция расширений:** Ошибка вида `"$basetexture" "models/my_prop/texture.vtf"` гарантированно сломает материал. Движок сам подставит нужное расширение, ориентируясь на тип параметра.
- **Слеши в путях:** В экосистеме Valve в качестве разделителя папок используются только прямые слеши `/` (`"models/props/texture"`). Обратные слеши `\`, скопированные из проводника Windows, движком не поддерживаются.
- **Комментарии в коде:** Для ведения заметок внутри VMT используйте двойной прямой слеш `//`. Все, что написано в строке после него, полностью игнорируется компилятором.
