## LOD (Level of Detail)

**LOD (Уровень детализации)** — это встроенная технология оптимизации в движке [[Source Engine 1|Source]], предназначенная для динамического снижения нагрузки на графический процессор (GPU) и центральный процессор (CPU). Она автоматически подменяет высокополигональную геометрию модели на её упрощенные (низкополигональные) копии по мере удаления объекта от камеры игрока.

Ключевые особенности механики

- **Принцип работы:** На близком расстоянии игрок видит проработанную модель с десятками тысяч полигонов и сглаженными контурами. Когда объект удаляется и занимает на экране всего несколько пикселей, движок мгновенно переключает рендер на грубую геометрию. Это позволяет экономить миллионы треугольников в кадре.
- **Применение в Garry's Mod:** Настройка LOD критически важна для серверов с высокой плотностью игроков, кастомного транспорта и пропсов. Без оптимизации LOD отрисовка нескольких детализированных моделей автомобилей или скинов в одной сцене способна просадить FPS даже на мощных системах.
- **Где хранятся данные:** Вся информация об индексах переключения геометрии и дистанциях запекается при компиляции в бинарный файл индексации вершин **`.dx90.vtx`**.

## 📐 Архитектура и синтаксис в файле компиляции (.QC)

Объявление уровней детализации происходит в теле `.qc` файла с помощью команды **`$lod`**. Для каждого уровня задается пороговая дистанция переключения и правила подмены исходных мешей.

Базовый синтаксис блока команды:

qc

```
$lod <дистанция_в_дюймах>
{
	replacemodel "исходный_меш.smd" "упрощенный_меш_lod.smd"
	replacematerial "старый_глянцевый_vmt" "новый_матовый_vmt" // Опционально
	removebone "имя_кости" // Опционально
}
```

Используйте код с осторожностью.

_Примечание:_ Дистанция в Source измеряется в игровых юнитах (дюймах). Например, `100` юнитов — это примерно 2.5 метра. Значение дистанции указывает компилятору, на каком расстоянии данный уровень LOD становится **активным**.

## 🛠️ Практический пример: Настройка трех уровней LOD для пропса

Рассмотрим классическую схему ступенчатой оптимизации сложного объекта (например, статуи или элемента окружения), которая плавно снижает детализацию до минимума.

qc

```
$modelname "props/custom_statue.mdl"
$cdmaterials "models/props/"

// Базовая высокополигональная модель (LOD 0 — до 400 юнитов)
$body "body" "statue_high.smd" 

// LOD 1: Включается на расстоянии ~10 метров. Полигонаж снижен на 50%.
$lod 400
{
	replacemodel "statue_high.smd" "statue_lod1.smd"
}

// LOD 2: Включается на расстоянии ~20 метров. Полигонаж снижен на 75%.
$lod 800
{
	replacemodel "statue_high.smd" "statue_lod2.smd"
}

// LOD 3: Экстремальный уровень (Лод-заглушка) на расстоянии ~40 метров.
$lod 1600
{
	replacemodel "statue_high.smd" "statue_lod3.smd"
	// Отключаем тяжелые кубмапы на дальней дистанции для разгрузки GPU
	replacematerial "statue_gold_shining" "statue_gold_matte" 
}

// Финальная заглушка (Shadow LOD): рендерит плоский меш для расчета тени
$shadowlod
{
	replacemodel "statue_high.smd" "statue_lod2.smd"
}

$sequence "idle" "statue_high.smd" fps 1
```

Используйте код с осторожностью.

## ⚙️ Продвинутая оптимизация: Отключение костей (`removebone`)

При оптимизации сложных анимированных персонажей (NPC/Playermodels) основную нагрузку на CPU создает анимационный конвейер — расчет вращения костей и скиннинга вертексов.

Команда **`removebone`** внутри блока `$lod` позволяет аппаратно «отключать» кости скелета на расстоянии.

- _Как использовать:_ На расстоянии 30 метров игроку не нужно видеть анимацию движения пальцев рук, шевеление подсумков или цепочек на броне.
- _Пример кода:_

qc

```
$lod 1200
{
	replacemodel "player_high.smd" "player_lod2.smd"
	// Склеиваем кости пальцев с костью кисти руки (анимация пальцев отключается)
	removebone "ValveBiped.Bip01_L_Finger0"
	removebone "ValveBiped.Bip01_R_Finger0"
	removebone "ValveBiped.attachment_pouch"
}
```

Используйте код с осторожностью.

При удалении персонажа движок перестает тратить такты процессора на расчет этих костей, жестко привязывая вертексы упрощенного меша к ближайшей родительской кости.

## 🛑 Известные баги, лимиты и технические ограничения

- **Эффект «Поппинга» (Грубое переключение на глазах):**
    - _Причина:_ Слишком резкий перепад полигонажа между уровнями (например, переход от 30 000 полигонов сразу к 500) либо неверно подобранная дистанция. Игрок будет четко видеть, как геометрическая форма объекта деформируется и «прыгает» при движении.
    - _Решение:_ Шаг снижения полигонажа должен быть плавным (LOD1 — 50%, LOD2 — 25% от исходника). Используйте команду **`$lod`** с плавной прогрессией дистанций.
- **Баг «Улетающих полигонов» (Взрыв меша):**
    - _Причина:_ Ошибка скиннинга при автоматической генерации лодов (например, через модификатор _Decimate_ в Blender). Если при уменьшении полигонажа были случайно удалены вершины, к которым крепились важные кости скелета, упрощенный меш при переключении вывернет наизнанку, а вершины растянутся в бесконечные острые иглы по всей карте.
    - _Решение:_ При оптимизации геометрии в Blender всегда вручную проверяйте привязку векторов вершин (_Vertex Weights_) на низкополигональных копиях.
- **Конфликт с бодигруппами ([[Bodygroups]]):**  
    Если на модели объявлены бодигруппы, блок `$lod` обязан содержать инструкции по замене **для каждого** файла геометрии, участвующего в бодигруппах. Если оптимизировать только базовое тело, но забыть про сменные шлемы, то при удалении камеры шлем останется высокополигональным и начнет «левитировать» отдельно от упрощенной головы.

## 🔍 Как проверить работу уровней LOD прямо в игре

Для визуального контроля оптимизации моделей в Garry's Mod используйте консольные команды (требуется `sv_cheats 1`):

- **`r_lod <номер>`** — принудительно переключает всю геометрию в мире на конкретный уровень LOD.
    - `r_lod 0` — заставляет движок всегда рендерить максимальное качество (LOD 0) независимо от расстояния. Идеально для красивых скриншотов.
    - `r_lod 3` — принудительно включает максимальную оптимизацию для проверки качества лод-мешей.
- **`mat_wireframe 1`** — сетка полигонов поможет наглядно увидеть, как плотность треугольников на объекте уменьшается по мере того, как вы отходите от него.
